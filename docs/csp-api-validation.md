Current official SDK `common/ac_web.lua` documents asynchronous `web.get`, `web.post`, `web.request` callbacks and WinHTTP timeouts; the Lua apps wiki explicitly warns that unloaded apps lose in-memory state except persisted storage. Neither declaration proves crash-safe atomic queue writes, server acknowledgement semantics, station token refresh, or actual Windows behavior. The client uses `ac.storage` for best-effort pending-review records with read-back, never network submission. Protocol version 1 requires `protocol_version`, `station_id`, `lap_id`, `session_id`, `pilot_id`, `raw_ms`, and event-specific `events`; status conventions also differ by event (`valid` for autocross/skidpad; `PENDING_REVIEW` for endurance). No station assignment/heartbeat/token binding is implemented. Operator-supplied start and ordered checkpoint gates separate a complete outlap from subsequent timed provisional routes; they do not prove installed asset identity or automatic scoring. `full_loop_proven` deliberately remains false for gate-count evidence alone. A local provisional route is **not** a server lap.\n\n`core.lua` implements segment crossing and corrected-time formulas, but `RiceTrials.lua` deliberately never calls scoring: automatic cone contact, off-course re-entry, and skidpad R,R,L,L classification are not established. No generated track geometry, map coordinates or substitute Rice track are embedded. The newly supplied archives contain `FSAEJ_Endurance/FSAEJ_Endurance.kn5` (12,204,024 bytes) and `FSAEJ_Skidpad/FSAEJ_Skidpad.kn5` (9,582,971 bytes), plus AI fast lanes, map/config files and Physics KN5. `data/map.ini` offsets/scales and camera positions are not surveyed timing gates. Do not substitute `RICE_FSAE_2027_AUTOCROSS_V1`, infer route geometry, or redistribute archives. `script.configure` is commissioning-only, operator-attested, and **not a verified live asset-hash or track-identity check**. Until a live identity/hash binding and surveyed gates are independently validated, leave configuration unset: timing/networking remain disabled. The `web.post` JSON payload is provisional and **not** an agreed server protocol; do not point it at production without contract integration and server-side verification.
