# Deployment

## Artifacts and build

From the repository root, `python3 packaging/build-linux.py` creates three **source-only** ZIPs in `dist/`: `RiceRacing_Trials_{Client,Server,Complete}.zip`. Each has a prominent `SOURCE_ONLY_NOT_READY_FOR_OFFICIAL_TRIALS.txt` marker. Linux does not produce a Windows executable. The server source package needs Python 3 on the target. The complete ZIP includes source and documentation; none of the archives contain game binaries, cars, tracks, session databases, or credentials.

On Windows with Python 3 and the `py` launcher, run `powershell -ExecutionPolicy Bypass -File packaging/build.ps1 -Version 0.1.0`. This builds `RiceTrialsServer.exe` from `server/app.py` with PyInstaller 6.16.0, bundles leaderboard static resources, and emits three `*-win64.zip` archives: client (Lua app plus read-only inventory kit), server (frozen executable plus launch scripts), and complete (both). Build host needs Python; deployment of the Windows server executable does not, but running the client inventory script needs Python 3. SHA-256 digests are printed. `.github/workflows/windows-package.yml` (manual dispatch only, no release publishing) tests, builds, checks archives, smoke-tests the frozen server and runs the Windows E2E harness described under Server. A CI pass does not establish AC/CSP rig compatibility.

## Client station

Install licensed Assetto Corsa, approved CSP, and the externally obtained FSAEJ Endurance, FSAEJ Skidpad and MFT02 assets from their rights holders; these ZIPs supply none. Obtain the **approved SHA-256 for each original download independently** (do not trust the hash printed by a downloaded package). Extract the client or complete ZIP. Run `powershell -ExecutionPolicy Bypass -File .\install.ps1 -AssettoRoot 'C:\path\to\assettocorsa' -EnduranceZip 'C:\downloads\FSAEJ_Endurance.zip' -EnduranceSha256 '<approved 64-hex digest>' -SkidpadZip 'C:\downloads\FSAEJ_Skidpad.zip' -SkidpadSha256 '<approved 64-hex digest>' -CarArchive 'C:\downloads\MFT02_v1.42.rar' -CarSha256 '<approved 64-hex digest>' -StationId 'station-1' -ServerUrl 'https://trials.example.org' -Preflight` first, then repeat without `-Preflight` to install. Preflight prints PASS or stops at the first diagnostic failure and changes nothing. The installer hashes the actual supplied archives and checks exact installed folder IDs under `content\tracks\FSAEJ_Endurance`, `content\tracks\FSAEJ_Skidpad`, and `content\cars\madformulateam_mft02`, plus root KN5 models / `data\car.ini`. It does **not** unpack or copy third-party mods; matching archive hashes and folder names do not prove the installed files came from those archives. Independently verify installed bytes, content versions, rights and rig behavior before official use. Installation stages only root Lua files and `manifest.ini` into `<AssettoRoot>\apps\lua\RiceTrials`; it requires a `dwrite.dll` CSP-loader candidate and still needs in-game CSP verification. An existing app is refused unless `-BackupDirectory 'D:\protected\app-backups'` names an already existing directory outside `apps\lua`; upgrade moves the old app there and restores it on install failure. Stop AC/CSP first. Enable the app and check loader behavior on the actual rig. The app is advisory and timing/scoring remains disabled until commissioning and identity/calibration validation; see `docs/windows-validation.md` and `docs/csp-api-validation.md`. There is no station desktop executable or LocalAppData application directory.

On installation (not `-Preflight`), run under the **same Windows account as the AC/CSP process**: the script prompts for a station token with `Read-Host -AsSecureString`, never takes it on the command line, and generates **`<AssettoRoot>\apps\lua\RiceTrials\station_config.lua`** containing the fields `server_url`, `station_id` and `station_token`, with each UTF-8 byte Lua-decimal-escaped. The staging folder and config file receive restricted NTFS ACLs (current user, administrators and SYSTEM only); an app upgrade backup may contain the previous credential and must be protected or destroyed after rotation. This local file is plaintext at rest for the AC user despite ACLs, not DPAPI-encrypted; rotate it if the station account is compromised. The app now attempts a guarded `require('station_config')` on its first update and, if the settings are present, calls `script.connect` to retrieve a server-authenticated assignment and send heartbeat. Its **module resolution, autostart, HTTP APIs and persistence must still be proven under CSP on the rig**; Linux Lua tests do not establish that. Never ship the generated file; both builders exclude `station_config.lua`, and CI rejects it. Provision station token in the server's protected store independently; official scoring remains unverified.

Run the read-only inventory from the extracted client/complete ZIP with `py -3 tools\validation.py --assetto-root 'C:\path\to\assettocorsa' --output 'D:\protected\station-inventory.json'`. It records installed `Physics.kn5`/`Dummy.kn5` hashes against offline landmarks, the selected car's `data.acd` or `data\car.ini` hash, and CSP-loader indicators. `ready` is **always false**: matching hashes are evidence, not proof of a selected layout, live car ID, route, calibration or CSP execution. Keep the JSON off the release media. Record independently approved original-archive hashes, installed bytes and operator/video evidence in the signed checklist.

## Server

Extract the server or complete ZIP to a protected directory. For the source ZIP, from the extracted directory run `python3 -m server.app --db /path/to/durable/trials.sqlite` inside `RiceTrialsServer` (or `python3 server/app.py` from there); set `RICE_ADMIN_TOKEN` and `RICE_STATION_TOKENS` (JSON mapping station IDs to distinct secrets) in the process environment through an external secret manager. For the Windows ZIP, run `powershell -File .\configure-secrets.ps1 -SecretsPath 'D:\protected\rice-secrets.xml' -StationIds station-1,station-2` **as the dedicated server account**; prompts use SecureString and Windows DPAPI encrypts the exported CLIXML for that account/machine. Never copy the secret file into a bundle, source tree or artifact. Restrict its NTFS ACL to the server account and administrators. Launch from the extracted ZIP with `powershell -File .\start-server.ps1 -SecretsPath 'D:\protected\rice-secrets.xml' -DatabasePath 'D:\protected\trials.sqlite'`; the launcher checks an absolute DB path and loopback bind, decrypts only in-process, starts the frozen EXE in the foreground, and clears inherited environment variables on exit. Rotate tokens on compromise. Windows process administrators can still inspect process memory; this is not a hardened secret vault.

Launched this way, `start-server.ps1` **supervises the exe**: if `RiceTrialsServer.exe` exits with a non-zero code it is relaunched after `-RestartDelaySeconds` (default 10 s), up to `-MaxRestarts` times (default 5; the budget resets after 10 minutes of healthy uptime). Each start writes its own `logs\server-<UTC>.{out,err}.log`. Exit code 0 is not relaunched. When the budget runs out the script fails with the last error log path.

For unattended start, run from the extracted ZIP, in an elevated PowerShell: `powershell -File .\server-admin.ps1 -Action RegisterTask -SecretsPath 'D:\protected\rice-secrets.xml' -DatabasePath 'D:\protected\trials.sqlite'`. It asks for the dedicated server account with `Get-Credential` (the same account that ran `configure-secrets.ps1`, or DPAPI cannot decrypt), grants that account **Log on as a batch job** (`SeBatchLogonRight`, which a new local account lacks and without which the task fails at logon with `0x80070569`), and registers a task that runs *At startup*, whether the user is logged on or not, `powershell.exe -File start-server.ps1 ...`, with no time limit. The password is never placed in a command line or file. Task Scheduler's `RestartCount` only retries a task that fails to launch; a crashed exe is handled by the supervisor above. Grant that account read/execute on the deployed folder and write on the DB parent, and keep other users out of the secrets and data. Test `Start-ScheduledTask -TaskName RiceTrialsServer`, then a real reboot, and check task history.

**Stopping the server:** use `powershell -File .\server-admin.ps1 -Action Stop`. It stops the task, the `start-server.ps1` supervisor of this release and the exe, and fails unless the port is free afterwards. **Killing only `RiceTrialsServer.exe` (Task Manager, `Stop-Process`) is treated as a crash and the server comes back in about 10 seconds.** Start it again with `Start-ScheduledTask -TaskName RiceTrialsServer`. `-Action Restore` stops the server the same way, restores, runs `--check`, and restarts the task only if it was running. Stop the server before replacing the bundle or copying the DB by hand; `-Action Backup` works with the server running. The server defaults to `127.0.0.1:8080`; terminate TLS at a protected reverse proxy before remote access, or bind a private LAN address with `-AllowLanBind` plus `-Action FirewallRule` (Private profile only).

Windows CI (`.github/workflows/windows-package.yml`, manual dispatch) runs `tests/windows/e2e-windows.ps1` on a real Windows runner against the built package: installer, ACL, DPAPI per account, the frozen server through `start-server.ps1`, API, backup/restore, LAN bind, firewall rule, the scheduled task under a dedicated local account, crash recovery and `-Action Stop`. A real reboot of the runner and anything inside Assetto Corsa/CSP are **not** covered: the AC root there is a fixture.

## Rollback

Stop the server with `server-admin.ps1 -Action Stop` before upgrading; use the authenticated `/api/admin/backup` SQLite backup endpoint or stop the process and copy the DB with its sidecar files, then restore/test in isolation. Retain the previous server bundle and DPAPI secrets securely. Stop AC/CSP before replacing the Lua app. On upgrade use `-BackupDirectory` to preserve the previous app; `powershell -File .\uninstall.ps1 -AssettoRoot 'C:\path\to\assettocorsa' -Preflight` inspects first, then omit `-Preflight` and confirm to remove it; optional `-BackupDirectory` moves it to a unique backup path instead of deleting. Never remove AC, CSP, tracks, car assets, or server data during client uninstall. Revalidate on the physical rig before official operation.
