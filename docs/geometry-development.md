The records were inspected from the ZIPs; no track limits or cone positions were assumed. The SVGs show only that AI path and mark its first point. `track/calibration/timing-landmarks.json` already contains timing dummies for both tracks, explicitly **not active** as scoring gates.
- The official clone [JSAE-ARCHIVES/FSAEJ-simulator](https://github.com/JSAE-ARCHIVES/FSAEJ-simulator) contains [`InvalidateLap/InvalidateLap.py`](https://github.com/JSAE-ARCHIVES/FSAEJ-simulator/blob/main/InvalidateLap/InvalidateLap.py): lines 84-106 read `info.physics.numberOfTyresOut`, count edges after returning to the normal state, and mark the lap spoiled. Its [README](https://github.com/JSAE-ARCHIVES/FSAEJ-simulator/blob/main/README.md) lines 125-135 admits that consecutive/rapid pylon hits may not be counted, that it is **indicative only**, and that the feature is for Ecopa only (22 Jul 2025). - The [official CSP SDK `ac_car_cphys.lua`](https://github.com/ac-custom-shaders-patch/acc-lua-sdk/blob/main/ac_car_cphys.lua) documents `isValidTrack` as physics surface data. ## Evidence API (`client/detectors.lua`)

- `off_course{source='ac_physics_numberOfTyresOut', min_out=2}` -> `observe({numberOfTyresOut=0..4})`: counts **wheels-out episodes** only on the entry edge, after returning below the threshold. `unknown` for a missing/erroneous sample; it neither approximates a cone nor issues an official penalty. Confidence `physics_proxy_uncertified`.
- `slalom{version='slalom-gates-v1',status='surveyed',survey_id=...,asset_sha256=...,gates={...}}`: each gate requires `id`, `a,b,pylon` in AC x,z meters, `direction` +/-1, alternating `side` left/right and a positive `clearance_m`. `side` means the negative/positive projection of `a->b` relative to the pylon; it is **not** the driver's left/right. Segments must be directed and measured. Rejected: missing plan, invalid point, wrong sequence, passing on the wrong side, or sampling that skips several gates. Only `sequence_observed`, never full-course validation or an official result. Confidence `surveyed_geometry_offline` even when the operator declares `surveyed`: the text string does not prove the survey.
- `cones()` -> `observe(evidence)`: proximity or generic `collision` contact = `unknown`/`review`; only `operator_adjudication` with `cone_id`, `contact=true`, `decision='hit'`, `reviewer`, `evidence_id` counts **distinct human decisions per cone**, deduplicated. Confidence `operator_review_only`, `official=false`; no physical detector or automatic feed is implemented. The operator must keep the video/telemetry referenced by `evidence_id` outside the engine.
- None of them is wired into `core.lua`, `RiceTrials.lua` or the server. Session, track hash, rig and rules must be verified externally; never trust a client-supplied `surveyed` label to publish a leaderboard.

The `ai-path-candidate-v1` JSON files and matching SVGs are **uncertified candidates**. The `survey-template-v1.json` files are empty (`gates=[]`, `status='candidate'`), carry the hash of the respective `Physics.kn5` and do not activate detectors. To enable gates: survey on the rig the real geometry and direction of travel, the identity/position of each pylon, the car's width/footprint and tolerances; link each gate to its evidence and to the installed track hashes, review video/collisions and check against the judge and the rules; run tests for false positives, sampling skips and session changes. There is no measured boundary polygon and no proven API for individual pylon contact. Do not use the AI line or `IS_VALID_TRACK` as a proxy for a homologated corridor.
